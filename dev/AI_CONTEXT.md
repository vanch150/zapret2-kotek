# Zapret2 Kotek — Контекст проекта для ИИ (AI_CONTEXT)

> **Прочитай этот файл ПЕРВЫМ перед любым аудитом, рефакторингом или правкой кода.**
> Он лежит в `dev/AI_CONTEXT.md`: автоматически попадает в лёгкий архив для ИИ (`dev/PACK_FOR_AI.bat`), но **не попадает** в релизный архив для пользователей (`dev/BUILD_RELEASE.bat` собирает релиз по белому списку).

---

## 1. Как устроена работа с проектом и архивом для ИИ

- **Лёгкая прослойка (`dev/PACK_FOR_AI.bat`):** автор передаёт код в ИИ через облегчённый архив (`dev/zapret2-kotek-v<ver>-code.zip`), где тяжёлые бинарники, `lua/`, картинки и `ipset-all.txt` заменены пустыми заглушками `*.stub.txt` ради минимального веса.
  - **Не считать** файлы `*.stub.txt`, папку `dev/` и `.gitignore` в этом архиве «мусором релиза» или «отсутствующими бинарниками» — `dev/build_release.ps1` сам собирает чистый пользовательский релиз с реальными бинарниками и без `dev/`.
  - Личные значения `secret=`, `cfproxy_domain=`, `cfproxy_worker_domain=` автоматически вырезаются при упаковке.
- **Удобство запуска для автора:** автор запускает все dev-утилиты двойным кликом, а не руками из консоли. Для каждого нового скрипта в `dev/*.ps1` обязательно делать `.bat`-лаунчер рядом.
- **Философия проекта:** утилита для обычных пользователей (друзей и родственников) на домашних ПК по принципу «в 1 клик», но с вариативностью в настройках. Безопасность важна, однако **не предлагать параноидальные усложнения, которые ухудшают стабильность, скорость или простоту работы** (если проблема реальная — объяснять конкретный сценарий поломки).

## 2. Осознанные решения автора (НЕ баги — не ломать)

- **Название и дизайн:** **Zapret2 Kotek** (`vanch150/zapret2-kotek`), маскот строго **«Котек»** (через `е`, не «Котик»). Палитра WPF GUI — тёмная (*Green-black and bone*) с **динамическим акцентом из системного цвета Windows (DWM)** (фоллбэк `#9FC7B8`). Спрайты `utils/kotek*.png` (268×280, ~58 КБ) сжаты намеренно.
- **Telegram WS Proxy — 20 сторонних Cloudflare-доменов (`DefaultCfDomains`):** используются **НАМЕРЕННО** как встроенный fallback-пул на случай, когда провайдер режет прямые IP Telegram. Не удалять этот пул и не флагать его как уязвимость.
- **Telegram WS Proxy — порт `:80` БЕЗ отключения и БЕЗ задержки:** равноправная одновременная гонка `ws://:80` и `wss://:443` сделана **НАМЕРЕННО**. Если отключить `:80` (`allow_plain_ws80=0`) или добавить искусственную задержку перед `:80` (`headStartDelay`), в Telegram начинают зависать загрузка и отправка фото/видео из-за 16-КБ TLS-блока ТСПУ (внутри WS трафик всё равно сквозно зашифрован MTProto AES-CTR).
- **Telegram WS Proxy — `smart` и секрет:** в режиме `smart` медиа с DC2 сначала пробуют прямой `kws2-1.web.telegram.org`, и только при отказе идут через Cloudflare. Секрет в `HKLM:\SOFTWARE\Zapret2\TgWsSecret` **не удалять** в `utils/uninstall.ps1` (чтобы при переустановке Telegram Desktop не плодил дубликаты прокси).
- **Обход ИИ (`utils/ai_bypass_helper.ps1`):** раздел называется **«Обход ИИ»** (не «Обход Gemini»), работает через Windows NRPT + SmartDNS (`lists/ai-dns-pool.txt`), выбор 7 сервисов галочками + `lists/ai-custom-domains.txt`, при миграции со старого конфига дефолт `gemini`. Кнопка «Все» намеренно **не** трогает `Claude` (включается только вручную). При активном системном VPN/прокси «Обход ИИ» автоматически ставится на паузу и возвращается после отключения VPN. Отключение NRPT идёт напрямую через реестр `DnsPolicyConfig` (быстро и без зависаний WMI/CIM). Встроенный чат/API-ключи Gemini в GUI не нужны. Раздельные настройки QUIC и DoH в браузере сделаны намеренно (NRPT совместим с отключённым QUIC, но конфликтует с DoH).
- **Списки доменов:** не удалять `exitlag.com`, `exitlag.io`, `speed.cloudflare.com`, `7tv.app`, `7tv.io`, `7tv.gg` из `lists/list-general.txt`. В кнопке «Пауза» (`utils/pause_resume.ps1`) драйвер `WinDivert` должен выгружаться полностью (именно это реально важно для античитов; домены в `list-exclude.txt` лишь страхуют лаунчеры от обрывов).
- **Обновления:** ядро `bol-van/zapret2` напрямую у пользователей **не** обновляется (только проверенные релизы из `vanch150/zapret2-kotek`). Проверка **`SHA256SUMS.txt` в `utils/self_update.ps1` — ОБЯЗАТЕЛЬНАЯ** (fail-closed ради стабильности и защиты от битых загрузок; `dev/PUBLISH_GITHUB.bat` генерирует её автоматически). Фоновое автообновление запускается в простое ПК (`-RunOnlyIfIdle` + `-StartWhenAvailable`), а не мешает играм/звонкам.
- **Прочее:** `[DEV]`-режим в GUI при наличии `dev/`/`.git/` отключает промпты переноса папки; `utils/wf_priority.conf` намеренно скрыт от GUI.

## 3. Технические инварианты (памятка для ИИ, чтобы не сломать Windows)

- **Windows PowerShell 5.1 строго:** никаких операторов PS 7+ (`??`, `?.`, `?:`, `&&`, `||`, `-AsHashtable`, `ForEach-Object -Parallel`).
- **C# 5 / .NET Framework 4.x (`csc.exe /warn:4`) строго:** `utils/TgWsProxyService.cs` компилируется системным `csc.exe` без внешних зависимостей — никаких фич C# 6+ (`$"..."`, `?.`, `nameof()`, `out var`, `using var`, `await` в `catch`/`finally`).
- **Кодировки и переводы строк (критично!):**
  - Все `*.ps1` — **UTF-8 с BOM (`EF BB BF`) + CRLF** (без BOM в PS 5.1 ломается кириллица).
  - Все `*.bat`, `*.cs`, `*.conf`, `*.txt`, `*.json`, `*.xaml`, `*.md`, `.gitignore`, `lists/*`, `bin/filters/*` — **UTF-8 без BOM + CRLF**.
  - Никаких буквальных `TAB` (`0x09`) внутри строковых путей и никаких поломанных `-Encoding UTF8` внутри имён переменных.
- **WPF и локализация Windows:**
  - В WPF-таймерах и событиях **запрещён `.GetNewClosure()`** (в PS 5.1 изолирует `$script:` и вешает флаги вроде `$script:BgOpBusy`; состояние передавать через `.Tag`).
  - Картинки `kotek*.png` / `kotek.ico` грузить через `BitmapCacheOption.OnLoad` (иначе блокируются при `self_update.ps1`).
  - При парсинге `sc query` / `netsh` не завязываться на английские слова (`STATE`, `timestamps`) — на русской Windows вывод локализован.
- **Права `NT AUTHORITY\NetworkService` (`*S-1-5-20`):** служба `zapret-tgws` работает под `NetworkService`, который не входит в `BUILTIN\Users`. После любого `icacls /inheritance:r` сохранять `*S-1-5-20`: `(RX)` на корень/`utils`/`bin`/`bin\tg-ws-proxy.exe`, `(R)` на `utils\tgws_proxy.conf`, `(OI)(CI)(M)` **только на `bin\logs\`** (для ротации `tg-ws-proxy.log` на 5 МБ). Бинарник проверяется двойным хэшем `CS=`/`EXE=` в `bin\tg-ws-proxy.sha256` и слушает только loopback.
- **Стратегии и NLM:** 10 базовых стратегий в `strategies/` + 12 в `configs_archive/`, двухступенчатый автоподбор (`utils/auto_setup.ps1`). Не путать фейки под разными `--payload=` с дублями. Специфика: `custom_auto_circular.bat` использует булев `disorder_after` (без `=-1`); в `custom_wssize_antifreeze.bat` `wssize` не выносить в верхний профиль; в `custom_delayed_split.bat` обязателен `--lua-desync=drop` после `send:delay=15`; NLM работает инверсией (`--nlm-filter-neg=1`), ручное сохранение в `gui_nlm_dialog.ps1` удаляет `nlm_auto.enabled`.
- **`dev/publish_github.ps1`:** `$ErrorActionPreference = 'Continue'` стоит намеренно (в PS 5.1 `git`/`gh` пишут прогресс в `stderr` и падают при `'Stop'`); везде проверяется `$LASTEXITCODE -ne 0`.

## 4. Открытые вопросы (можно улучшать и обсуждать)

- **Список целей бенчмарка (`utils/targets.txt`):** сейчас 27 целей (`17 CORE` + `10 EXT`) + 64-КБ тест по `speed.cloudflare.com` (`>= 32 КБ`) и пробник `redirector.googlevideo.com`. Автор пока думает над составом целей — предложения по улучшению точности подбора приветствуются.
- **Задержка `onboot` в `utils/autoupdate_task.ps1`:** сейчас стоит `PT30S`, автор считает 30 секунд неидеальными (сеть при старте Windows может не успеть подняться) — допустимо увеличить (например, до `PT2M`) по согласованию.
- **План на v1.1.1+ — автоподпись релизов (`SHA256SUMS.txt.sig`):** добавить генератор RSA-ключа (`dev/GEN_SIGN_KEY.bat` + `.ps1`, приватный ключ хранится локально вне git, публичный `utils/release_pubkey.xml` коммитится в репозиторий) и автоматическую подпись `SHA256SUMS.txt` → `SHA256SUMS.txt.sig` в `dev/build_release.ps1` и `dev/publish_github.ps1`. В v1.1.0 проверка `.sig` в `self_update.ps1` намеренно остаётся опциональной (активируется только при наличии `release_pubkey.xml`), чтобы текущие клиенты обновились без сбоев.
- **План на v1.1.1+ — опциональный секрет `INGEST_KEY` для телеметрии:** `dev/cloudflare_telemetry_worker.js` уже поддерживает заголовок `X-Kotek-Key` (проверка включается, как только в Cloudflare Workers добавить секрет `INGEST_KEY`), rate-limit 10 req/мин и деление длинных логов на 2 сообщения. При включении `INGEST_KEY` добавить отправку заголовка в `utils/telemetry_helper.ps1`.
- **План на v1.1.1+ — перенос папок и усиление ACL без ломки Рабочего стола:** при переносе из другой папки обязательно запускается начальный тест (`auto_setup.ps1`); не добавлять жёстких запретов на установку на Рабочем столе / произвольных дисках.
